## An example of the ANS algorithm

### Given:

- Characters: `a b a c`

### Initial Setup:

1. Predefine value: `11111`
2. Start encoding from here (decoding is also possible)
3. Assume the encoding table have been established, which is the same at both sides

### Table

| state | A   | B   | C   |
| ----- | --- | --- | --- |
| 1     | 2   | 3   | 5   |
| 2     | 4   | 6   | 10  |
| 3     | 7   | 8   | 15  |
| 4     | 9   | 11  | 20  |
| 5     | 12  | 14  | 25  |
| 6     | 13  | 17  | 30  |
| 7     | 16  | 21  |     |
| 8     | 18  | 22  |     |
| 9     | 19  | 26  |     |
| 10    | 23  | 28  |     |
| 11    | 24  |     |     |
| 12    | 27  |     |     |
| 13    | 29  |     |     |
| 14    | 31  |     |     |


### Encoding Process:

1. Output `1`, remainder `1111`, equivalent to `15` (since the table has no corresponding entry, move forward)

2. **Modify the output to three bits**, remainder `111`, equivalent to `7`

3. Lookup character `a`, found at row `16`, column `a`
    - `16` corresponds to `10000`
    - Output `0`, remainder `1000`, equivalent to `8`

4. Lookup character `b`, found at row `22` (row `8`, column `b`)
    - `22` corresponds to `10110`
    - Output `0`, remainder `1011`, equivalent to `11`

5. Lookup character `a`, found at `24`
    - `24` corresponds to `11000`
    - Output `0`, remainder `1100`, equivalent to `12`

6. Lookup character `c`, found at `30`
    - `30` corresponds to `11100`
    - **Final state**, output `11100`

### Final Encoded Value:

```
11000011100
```


### Decoding Process:

1. Start with encoded string: `11000011100`
    
2. Extract `1110`, corresponding to `30`, lookup row `6`, column `c`
    
    - Output `c`, remainder `6`, corresponding to `110`
        
3. Extract next `5` bits, `11000`, corresponding to `24`, lookup row `11`, column `a`
    
    - Output `a`, remainder `11`, corresponding to `1011`
        
4. Extract `2` bits, `10110`, corresponding to `22`, lookup row `8`, column `b`
    
    - Output `b`, remainder `8`, corresponding to `1000`
        
5. Extract `1` bit, `10000`, corresponding to `16`, lookup row `7`, column `a`
    
    - Output `a`, remainder `7`, corresponding to `111`
        
6. Extract `2` bits, `1111`, corresponding to `31`, lookup row `31`

    - There is no row `31` in the table, in fact `31` stands for `11111`, meaning the decoding is now complete. Output sequence is `caba`, the reverse gives `abac`. 

### Notes

- If modifying the number of bits to be output, both the left and right approaches can be valid.
- The encoding and decoding processes are consistent and reversible.
